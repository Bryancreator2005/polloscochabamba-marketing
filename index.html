1. Introducción

Nombre de la API: API Rest CRM - Pollos Cochabamba.

Objetivo: Facilitar la integración y sincronización de datos entre el departamento de Marketing (Panel Web) y el departamento de Ventas (Sistema en Visual Basic).

Descripción del Proyecto: Sistema backend desarrollado en Python (Flask) que expone servicios RESTful. Permite a los sistemas de facturación conocer las promociones activas en tiempo real y registrar la información de nuevos clientes en una base central de CRM.

Funcionalidades principales:

  • Lectura de catálogo de productos promocionales con precios actualizados.
  • Registro centralizado de clientes (Nombre y Teléfono) al momento de la venta.

2. Acceso y Autenticación

Método de autenticación utilizado: Entorno de Red Local (Sin Autenticación Restrictiva en fase de desarrollo).

Explicación: Actualmente, la API está diseñada para operar de forma interna en la intranet (Wi-Fi) de la empresa bajo la dirección IP 192.168.69.141. Al ser una red cerrada, las solicitudes no requieren un token criptográfico. Sin embargo, para simular un entorno de producción futuro, se ha definido una estructura base para API Keys.

Forma de envío (Fase de Producción planificada): Se enviará mediante los Headers de la petición HTTP bajo la llave X-API-KEY.

Ejemplo de Solicitud Autenticada (Futuro)

GET /api/marketing/promociones HTTP/1.1
Host: 192.168.69.141:5000
X-API-KEY: a1b2c3d4-pollos-cbba-9988
Accept: application/json

3. Rutas o Endpoints

La API expone actualmente dos rutas principales para la operativa del negocio.

GET /api/marketing/promociones

Descripción: Devuelve la lista completa de promociones activas creadas por el área de marketing.

Parámetros Requeridos / Opcionales: Ninguno.

Ejemplo de Respuesta HTTP 200 OK

{
  "status": "success",
  "total_promos": 2,
  "data": [
    {
      "id_promo": 101,
      "nombre_campana": "Promo Universitarios",
      "id_producto": 1,
      "precio_promocional": 15.00,
      "activa": true
    }
  ]
}
POST /api/marketing/clientes

Descripción: Registra la información de contacto de un nuevo cliente captado en caja.

Parámetros Requeridos (Body JSON)

ParámetroTipoDescripción
nombre RequeridoStringNombre del cliente.
telefono RequeridoStringNúmero telefónico o celular.

Ejemplo de Solicitud

{
    "nombre": "Luis Buezo",
    "telefono": "77123456"
}

Ejemplo de Respuesta HTTP 201 Created

{
  "status": "success",
  "mensaje": "Cliente Luis Buezo registrado en el CRM"
}

4. Formato de Datos

Todo el intercambio de información con la API se realiza utilizando el formato estándar JSON (JavaScript Object Notation).

  • Headers de Envío: Las solicitudes `POST` deben incluir obligatoriamente el header: Content-Type: application/json.
  • Estructura de Respuesta: Todas las respuestas incluyen un campo raíz llamado status ("success" o "error") para facilitar la validación del lado del cliente, acompañado del campo data (para consultas) o mensaje (para confirmaciones).
  • CORS: La API implementa políticas CORS cruzadas (flask_cors) para permitir lecturas desde navegadores en puertos distintos (Ej. Web frontend en el puerto 8000).

5. Dirección y Acceso a los Datos

El flujo de intercambio de información opera bajo la siguiente arquitectura Cliente-Servidor:

[Cliente Visual Basic / Web] ➔ [Red LAN (Wi-Fi)] ➔ [API Flask (Puerto 5000)] ➔ [Estructura de Datos CRM]

  • Qué envía el cliente: El cliente (Ventas) solicita datos de precios o envía paquetes JSON con nombres y teléfonos.
  • Qué procesa la API: El servidor en Python recibe, valida los formatos, calcula la longitud de los arreglos (ej. total de promociones) y procesa la lógica del negocio.
  • Qué devuelve: La API retorna respuestas HTTP estructuradas con códigos de estado exactos (200, 201, 404, 500) junto al JSON procesado.

7. Ejemplos de Consumo

Desde JavaScript (Frontend Web) - Método GET

fetch('http://192.168.69.141:5000/api/marketing/promociones')
  .then(response => response.json())
  .then(data => console.log('Promociones:', data))
  .catch(error => console.error('Error de red:', error));

Desde Visual Basic .NET (Equipo de Ventas) - Método POST

Dim client As New HttpClient()
Dim jsonData As String = "{""nombre"":""Carlos"",""telefono"":""78945612""}"
Dim content As New StringContent(jsonData, Encoding.UTF8, "application/json")

Dim response = Await client.PostAsync("http://192.168.69.141:5000/api/marketing/clientes", content)
Dim responseString = Await response.Content.ReadAsStringAsync()
Console.WriteLine(responseString)

Configuración en Postman

  • Método: Seleccionar POST o GET según el endpoint.
  • URL: http://192.168.69.141:5000/api/...
  • Body (solo para POST): Pestaña Body ➔ raw ➔ seleccionar JSON.

8. Manejo de Errores

La API utiliza códigos de estado HTTP estándar. Cualquier solicitud que falle retornará un JSON con la estructura del error.

Código HTTPSignificadoAcción requerida del Cliente
200 OKÉxito.Procesar la propiedad data de la respuesta.
201 CreatedRegistro Creado.Confirmar al usuario en pantalla que el guardado fue exitoso.
400 Bad RequestMala Petición.El JSON enviado en el POST está mal formateado o faltan campos obligatorios.
404 Not FoundNo Encontrado.Verificar que la ruta escrita en la URL sea exactamente la documentada.
500 Internal ErrorError de Servidor.Contactar al administrador backend. Posible falla de ejecución de Python.

Ejemplo de Respuesta de Error (Falta de datos)

{
  "status": "error",
  "mensaje": "El campo 'nombre' es obligatorio."
}
