1. Introducción

Nombre de la API: API Rest CRM & Marketing - Pollos Cochabamba.

Objetivo: Facilitar la integración y sincronización de datos bidireccional entre el departamento de Marketing (Panel Web Corporativo) y el inventario del departamento de Ventas en tiempo real a través de la red local.

Descripción del Proyecto: Sistema backend desarrollado en Python (Flask) operando en una arquitectura de doble puerto. Expone servicios RESTful permitiendo crear promociones, consumir inventarios mediante un puente de subred y registrar clientes en un CRM unificado.

Funcionalidades principales actualizadas:

  • Lectura e inserción del catálogo de productos promocionales (Combos).
  • Conexión externa automatizada (proxy) hacia el catálogo de insumos de Ventas (IP 192.168.68.157) utilizando la librería requests.
  • Registro centralizado de clientes (Nombre y Teléfono) al momento de la venta.

2. Acceso y Autenticación

Método de autenticación utilizado: Entorno de Red Local Corporativa (Sin Autenticación Restrictiva en fase de desarrollo actual).

Explicación: La API principal opera bajo la dirección IP 192.168.69.141 y el puerto 5000 con el host expuesto a 0.0.0.0. Al estar aislada en la intranet empresarial, confía en la seguridad física y de enrutamiento de la red. Para entornos de producción expuestos, se implementará autenticación vía tokens.

Forma de envío (Fase de Producción planificada): Se enviará mediante los Headers de la petición HTTP bajo la llave X-API-KEY.

Ejemplo de Solicitud Autenticada (Futuro)

GET /api/marketing/promociones HTTP/1.1
Host: 192.168.69.141:5000
X-API-KEY: a1b2c3d4-pollos-cbba-9988
Accept: application/json

3. Rutas o Endpoints

La API expone las siguientes rutas clave para gestionar el marketing y la conexión con inventarios externos.

GET /api/marketing/promociones

Descripción: Devuelve la lista completa de promociones y combos creados, incluyendo su estado de activación para renderizar el catálogo visual web.

POST /api/marketing/promociones

Descripción: Recibe el paquete de datos estructurado desde el formulario web (Puerto 8000) y registra una nueva campaña o combo en la base de datos.

Body Requerido (JSON)

{
  "id_producto": 105,
  "nombre_campana": "Súper Combo Fin de Semana",
  "precio_promocional": 85.50,
  "activa": true
}
GET /api/marketing/datos_externos

Descripción: Ruta especial que actúa como un puente (proxy). Al llamarla, Python se encarga de saltar de la red 69.x a la red 68.x, consultando internamente a http://192.168.68.157:5000/api/v1 y entregando la respuesta limpia al frontend, evadiendo así las restricciones estrictas de CORS y subred del navegador.

POST /api/marketing/clientes

Descripción: Registra la información de contacto de un nuevo cliente captado en caja para el sistema CRM.

4. Formato de Datos

Todo el intercambio de información con la API se realiza utilizando el formato estándar JSON (JavaScript Object Notation).

  • Headers de Envío: Las solicitudes POST deben incluir obligatoriamente el header: Content-Type: application/json.
  • Manejo CORS Integrado: El backend en Python incorpora la librería flask_cors. Esto es crucial porque el cliente web vive en el puerto 8000 y la API en el 5000. Flask-CORS firma digitalmente las respuestas para que el navegador confíe en el tráfico cruzado.
  • Prevención por Defecto: Formularios HTML incluyen event.preventDefault() y consumen la API usando la librería nativa fetch() de JavaScript para recargas asíncronas.

5. Dirección y Arquitectura de Conexión

El flujo operativo se divide en tres nodos distintos dentro de la Intranet, comunicándose de la siguiente manera:

[Cliente Web (HTML/JS)]   ➔ (Fetch API Puerto 5000)
    (Puerto 8000)                   │
          │                         ▼
[Usuario de Marketing]    [API Flask Central (192.168.69.141)]
                                    │
                                    ▼ (Librería Requests)
                      [API Ventas Inventario (192.168.68.157)]
  • Panel Web (Frontend): Interfaz corporativa alojada en el host local en el puerto 8000. Llama a Flask para cualquier operación de lectura/escritura.
  • Servidor Puente (Backend Flask): Procesa inserciones. Cuando se requiere el catálogo de Ventas, usa la librería requests en Python para superar la barrera entre las subredes (192.168.69.X vs 192.168.68.X).

7. Ejemplos de Consumo

Desde JavaScript (Frontend Web) - Insertar Promoción (POST)

const payload = {
    id_producto: 12,
    nombre_campana: "Súper Combo Universitario",
    precio_promocional: 25.00,
    activa: true
};

fetch('http://192.168.69.141:5000/api/marketing/promociones', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify(payload)
})
.then(res => res.json())
.then(data => alert('Combo guardado exitosamente'))
.catch(error => console.error('Error de red:', error));

Consumo de Datos Externos (Puente GET)

// El frontend consulta a su propio backend, y este consulta a Ventas
fetch('http://192.168.69.141:5000/api/marketing/datos_externos')
  .then(res => res.json())
  .then(data => console.log('Catálogo de Ventas (IP 157) recibido:', data));

Configuración Rápida en Terminal / Servidores

  • Levantar Frontend: python3 -m http.server 8000 --bind 0.0.0.0
  • Levantar Backend: source env/bin/activate && python3 marketing.py
  • Liberar puerto ocupado: fuser -k 5000/tcp

8. Manejo de Errores

La API utiliza códigos de estado HTTP estándar, integrando tolerancia a fallos mediante bloques try-except en Python y .catch() en JS.

Código HTTPSignificadoCausa / Acción recomendada
200 OKÉxito.La conexión y respuesta operan con normalidad.
201 CreatedRegistro Creado.Confirmación tras enviar un POST de Promoción o Cliente.
404 Not FoundNo Encontrado.Flask no ejecutado o endpoint escrito incorrectamente.
500 Internal ErrorError de Servidor.Aparece si la librería requests no logra conectar con la IP de Ventas (192.168.68.157 está apagada). La interfaz capturará el error sin romper el panel.

Ejemplo de Respuesta 500 Controlada (IP de Ventas Caída)

{
  "error": "No se pudo alcanzar la IP 192.168.68.157",
  "detalle": "Connection refused"
